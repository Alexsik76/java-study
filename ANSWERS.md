# Письмові відповіді

1. Що фізично містить JDK, чого немає в JRE?

Фізично JDK (Java Development Kit) містить усе, що є в JRE, плюс інструменти розробника, яких у JRE немає:
- Основні компоненти (утиліти та файли), наявні лише в JDK:
- Компілятор (javac): перетворює текстовий вихідний код (.java) у байт-код (.class).
- Архіватор (jar): пакує скомпільовані класи та ресурси у файли .jar.
- Декомпілятор (javap): дисасемблює та аналізує байт-код.
- Відлагоджувач (jdb): інструмент для пошуку помилок у коді (дебагінгу).
- Генератор документації (javadoc): автоматично створює HTML-документацію з коментарів.
- Утиліти моніторингу: засоби аналізу пам'яті, потоків та процесів JVM (jconsole, jmap, jstat тощо).
- Вихідні коди (src.zip): файли з вихідним кодом стандартної бібліотеки Java.

Коротко: JRE містить лише середовище для запуску програм, а JDK — додаткові інструменти для їх створення та тестування.

2. Чому байт-код не є машинним кодом і що з ним робить віртуальна машина під час виконання?
Машинний код — це набір інструкцій, зрозумілих конкретному фізичному процесору (наприклад, x86 або ARM). Байт-код — це універсальний проміжний код, створений для абстрактного процесора (Java Virtual Machine). Він не прив'язаний до архітектури реального обладнання чи операційної системи.

Що робить JVM з байт-кодом під час виконання:
JVM виступає "перекладачем", який перетворює байт-код у машинний код вашого пристрою безпосередньо під час роботи програми. Це відбувається двома способами:
-  Інтерпретація: JVM читає інструкції байт-коду одну за одною і відразу виконує відповідні їм машинні команди.
-  JIT-компіляція (Just-In-Time): JVM аналізує програму під час роботи, знаходить ділянки коду, які виконуються найчастіше ("гарячі точки"), і компілює їх у справжній машинний код. Це дозволяє виконувати їх зі швидкістю звичайних скомпільованих програм.

3. Що станеться, якщо виконати `java -cp out ua.sikorskyi.probe.SystemProbe`, попередньо видаливши каталог `out`, і яким буде текст помилки? Відповідь перевірте на практиці.

Java-машина не зможе знайти головний клас програми. Оскільки каталог out, вказаний як шлях пошуку класів (-cp), видалено, JVM не матиме звідки завантажити файл SystemProbe.class. Виконання програми відразу аварійно завершиться.

```
Error: Could not find or load main class ua.sikorskyi.probe.SystemProbe
Caused by: java.lang.ClassNotFoundException: ua.sikorskyi.probe.SystemProbe
```

4. Чим `-cp` відрізняється від `-jar` за способом визначення точки входу?

Відмінність полягає в місці, звідки Java-машина дізнається ім'я головного класу з методом main:

- При використанні -cp (classpath):
Точка входу вказується явно в командному рядку. Ви самі передаєте повне ім'я класу як аргумент команди.
Синтаксис: java -cp <шляхи> <ПовнеІм'яКласу>
Приклад: ```java -cp out ua.sikorskyi.probe.SystemProbe```
- При використанні -jar:
Точка входу визначається автоматично з маніфесту. В команді вказується лише шлях до архіву. JVM самостійно відкриває JAR-файл, шукає всередині файл META-INF/MANIFEST.MF і зчитує звідти обов'язковий атрибут Main-Class.
Синтаксис: java -jar <файл.jar>
Приклад: ```java -jar probe.jar```

Важлива особливість: Якщо ви запускаєте програму з прапорцем -jar, усі параметри -cp ігноруються системою. JVM шукатиме класи виключно всередині самого JAR-архіву.
